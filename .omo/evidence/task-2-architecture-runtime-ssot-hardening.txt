Implementation contract
- Sole publisher: .github/workflows/release.yml; serialized group release-production, cancel-in-progress=false.
- Trusted automated input: successful CI workflow_run from master and this repository; target is workflow_run.head_sha.
- Manual input: required lowercase 40-hex target and exact current remote master tip.
- Policy: breaking/! major, feat minor, fix/perf/refactor patch, everything else none.
- Highest reachable strict SemVer tag must equal global highest strict SemVer tag; duplicate same-commit tags resolve by SemVer; next version is monotonic.
- Decision artifact: publish, no-release, or superseded, including target, previous tag, optional next tag, reason, and immutable range.
- Source asset: git archive at target under resume-${TAG}/ piped to gzip -n -9, built twice, byte-compared, member-scanned, secret-scanned, extracted, installed, built, and Wrangler dry-run verified.
- Draft transaction: `release/publish` is a typed Go operational boundary over injected release/ref interfaces. All discovery happens before the first current-tip guard; the immediately following external operation is draft POST (or asset upload on resume). The second tip guard immediately precedes publish.
- Cleanup re-fetches both draft and tag, then requires draft status, exact target, run marker, persisted tag-ownership flag, and exact tag target before either DELETE. Any mismatch returns an error with zero deletion.
- Pre-existing/published tags are never cleanup candidates; interrupted same-run draft resumes; exact published target/name/digest/size reruns are idempotent and mismatches fail closed.
- The structurally parsed workflow invokes only `go -C tools/scripts run ./release/publish`; comment-only tokens and direct `gh` publication bypasses fail validation. Workflow and every new source file are at most 200 physical LOC.
- Parsed command classification combines mutation method, endpoint, and separate tag-ref arguments. It rejects release API POST/PATCH/DELETE, tag API POST/PATCH/DELETE, `git push --tags`/`refs/tags`, and `gh release create/edit/delete/upload` in every workflow, including standalone contents-write writers and variable repository paths.
- Effective GitHub API method inference follows the official `gh api` manual: `-f`/`--raw-field` and `-F`/`--field` (separate, equals, and compact forms) imply POST only when no explicit method is present; explicit `--method GET`/`-XGET` remains GET.
- Cloudflare Workers Builds remains the sole production deploy authority.
