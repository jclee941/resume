## 3. 당근 면접 스타일 (블로그/Gist 종합)

### 핵심 패턴

- **What 거의 안 묻고 How/Why 깊이 파고듬** (이력서 기반)
- "왜 그렇게 결정했나?" / "지금 다시 한다면?" 반복 질문
- 시스템 디자인 화이트보드 (직무 인터뷰)
- 라이브 코딩 (직무에 따라 짧게, 코더패드)
- 4:1 면접도 가능 (사업팀 사례)
- 긴 직무 인터뷰 길이 (코테와 Q&A 패턴)
- **꼬리질문** 매우 깊음, "이미 사전 검증된 기초보다는 무엇/왜" 위주
- 컬처핏: 대표/CTO 직접, "대화" 수준 깊이

### 함정 신호

- 이력서에 적었는데 모르면 즉시 감점
- 인성 질문이 예상보다 많이 나옴 (프론트엔드 회고에서 언급)
- "실제 경험을 묻는 것" → STAR 구조 + 구체 수치 필수

## 6. 라이브 코딩 (만약 1면접에 포함된다면)

### 당근 패턴 (다른 직군 회고 종합)

- **코더패드** 사용
- 문제 자체는 어렵지 않음, 풀고 나서 **"더 효율적으로 한다면?", "이 조건이라면?"** 꼬리질문
- 코딩 스타일 + 사고 과정 + 피드백 수용도 평가

### 보안 도메인 라이브 코딩 예상

- 로그 파싱 (정규식 또는 dict 처리) — 가장 흔함
- IOC 매칭 (해시/IP 리스트 vs 스트림)
- Rate limiting 알고리즘 (어뷰징 차단 시뮬레이션)
- 간단한 anomaly detection (z-score, IQR)
- API 보안 헤더 검증 함수

> 언어: Python 우선 (Ruby 가능하면 좋지만 필수 아님). "Python으로 먼저 작성 후 Ruby로 옮겨도 될까요" 정직하게 요청
  가능.

## 8. 면접 단계별 핵심 전략

### 1면접 (화상 인터뷰)

- 짧은 자기소개 외워서 신속하게
- 이력서 기반 이력 검증 (직접 한 일/판단/도구) 위주
- 라이브 코딩 가능성 있음 → 코더패드 환경 미리 익혀두기

### 2면접 (직무 인터뷰)

- **시스템 디자인 화이트보드 출제 가능성 높음** (어뷰징 탐지 또는 침해 탐지 체계)
- STEAMP 6단계 순서로
- "이미 알고 있는 정답"보다 **사고 과정 + 트레이드오프**
- MITRE ATT&CK TTP ID 자연스럽게 대표 사례 인용
- 4:1 가능 (CERT 리더 Toto, 보안팀 리더 Elliot, AppSec 멤버, 매니저)

### 3면접 (컬처핏 + 레퍼런스)

- 임원 또는 CTO 직접 (대화형 긴 직무 인터뷰 가능)
- "정말 경청하고 꼬리질문" 함 → 솔직함이 무기
- 본인 인생관/가치관 + 당근 핏 검증
- 레퍼런스: 직전 회사 사수/동료 복수 레퍼런스 미리 양해 구해두기
