# Code Style and Conventions

This document defines the canonical code style and conventions for the resume
monorepo.

## Overview

JavaScript with JSDoc is primary; TypeScript is used for types and selected
checked files. ESM is standard in apps and packages, with CJS where required by
root configuration. Node >= 22 is required.

## Language and Runtime

- JavaScript and JSDoc are primary; TypeScript files hold types and the strict
  typecheck allowlist
- Node >= 22 required (enforced by `.nvmrc`)
- ESM (`"type": "module"`) in all apps and packages
- CJS only for root config files (eslint.config.cjs, jest.config.cjs,
  playwright.config.js)
- Target: ES2022 (from jsconfig.json)

## File and Directory Naming

- Directories: kebab-case (e.g., `apps/portfolio/lib/`)
- Files: lowercase with dots/hyphens allowed (e.g., `generate-worker.js`)
- Contract files (uppercase): AGENTS.md, README.md, CHANGELOG.md, LICENSE
- Path aliases (from jsconfig.json):
  - `@lib/*` → `apps/portfolio/lib/*`
  - `@tests/*` → `tests/*`

## ESLint Rules

Key rules from eslint.config.cjs (ESLint 9 Flat Config):

| Rule            | Setting                          |
| --------------- | -------------------------------- |
| semicolons      | required                         |
| quotes          | single quotes, avoidEscape: true |
| no-var          | error                            |
| prefer-const    | warn                             |
| eqeqeq          | always, null: ignore             |
| no-eval         | error                            |
| no-implied-eval | error                            |
| no-new-func     | error (test files excepted)      |
| no-unused-vars  | warn (argsIgnorePattern: `^_`)   |

Test files (`tests/**/*.test.js`, `tests/**/*.spec.js`) have no-new-func
disabled.

Ignored patterns: node_modules, build outputs (worker.js, dist), coverage, logs,
.wrangler.

## Module Patterns

### Portfolio (apps/portfolio/)

- Pure functions in `lib/` — receive env, produce output, no side effects
- Build-time asset inlining — zero runtime I/O
- CSS variables for theming (see `src/styles/variables.css`)
- `worker.js` is generated by `generate-worker.js` — never edit directly
- Multi-language: `data.json` (ko), `data_en.json`, `data_ja.json`

### Job Dashboard (apps/job-dashboard/)

- All handlers extend `BaseHandler(db, cache, env)`
- KV entries MUST have TTL
- Rate limiting: 60 req/min per IP per endpoint

## Testing Conventions

| Test Type   | Location             | Framework  | Notes                 |
| ----------- | -------------------- | ---------- | --------------------- |
| Unit        | `tests/unit/`        | Jest       | `*.test.js`           |
| Integration | `tests/integration/` | Jest       | `*.test.js`           |
| E2E         | `tests/e2e/`         | Playwright | Separate test command |

Coverage (via Jest): global threshold 90% (see jest.config.cjs).

Critical: Never use `networkidle` in Playwright — use `domcontentloaded`.

## Commit and PR Standards

- Conventional Commits: `type(scope): imperative summary` (<=72 chars,
  lowercase)
- Types: `feat`, `fix`, `docs`, `refactor`, `test`, `ci`, `chore`, `perf`,
  `build`, `revert`
- Squash merge only
- ~200 LOC max per PR
- SHA-pin all GitHub Actions with `# vN` version comment (e.g.,
  `actions/checkout@v4 # v4.2.2`)

## Anti-Patterns

| Pattern                                           | Reason                       |
| ------------------------------------------------- | ---------------------------- |
| `as any`, `@ts-ignore`, `@ts-expect-error`        | Type safety                  |
| Empty catch blocks (`catch {}`)                   | Error swallowing             |
| Hardcoded credentials, resume IDs, session tokens | Security                     |
| KV entries without TTL                            | Resource leak                |
| Mutable action tags (`@v4`)                       | Reproducibility              |
| Naked Puppeteer without stealth                   | Detection risk               |
| Direct edits to `worker.js`                       | Build artifact (regenerated) |
| Merge commits                                     | Squash only                  |
| Manual `npm run deploy`                           | Blocked, use git push        |

## Formatting

Prettier configuration (.prettierrc):

| Option         | Value  |
| -------------- | ------ |
| semi           | true   |
| singleQuote    | true   |
| tabWidth       | 2      |
| useTabs        | false  |
| trailingComma  | es5    |
| printWidth     | 100    |
| bracketSpacing | true   |
| arrowParens    | always |
| endOfLine      | lf     |

Run `npm run format` or `npm run format:check`.

## CI Pipeline

GitHub Actions runs one read-only `Validate` job. It runs the configured
validation checks, including tests and a Wrangler dry-run; it does not run the
Playwright E2E suite or deploy. Run `npm run test:e2e` separately when E2E
coverage is needed. Cloudflare Workers Builds owns production deployment from
the root Wrangler configuration.
