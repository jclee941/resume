# 지원 우선순위 스코어카드

각 공고를 지원 전 아래 기준으로 빠르게 채점한다. 총점이 낮으면 지원하지 않고, 같은 시간에 더 맞는 공고를 찾는다.

## 점수 기준

| 항목 | 점수 | 기준 |
| --- | ---: | --- |
| 보안 인프라/SecOps/SRE 직접 관련 | 0-3 | 직무명이 보안 운영, 보안 인프라, DevSecOps, SRE, Observability와 직접 연결되는가 |
| 기술 매칭 | 0-3 | FortiGate, Splunk, SIEM, Linux, Python, Ansible, Terraform, Grafana, Cloudflare 중 2개 이상 포함 |
| 금융/규제/감사 도메인 | 0-2 | 금융권, 개인정보, 감사, 컴플라이언스, 보안 심사 경험이 가치로 작동하는가 |
| 포트폴리오 데모 연결성 | 0-2 | resume.jclee.me, Grafana/ELK, GitHub 자동화 경험을 자연스럽게 설명할 수 있는가 |
| 자동지원 안전성 | -3-0 | 법적/국적/민감정보/캡차/긴 서술형 필드가 많으면 감점 |

지원 기준:
- 7점 이상: 맞춤 지원
- 5-6점: 시간이 남을 때 지원
- 4점 이하: 보류

## 감점해야 하는 신호

- “풀스택 개발자”인데 보안/인프라 요구가 거의 없음
- AI/LLM만 강조하고 운영·보안·인프라 접점이 없음
- 국적, 비자, 보훈/장애, 법적 고지 등 자동 답변 금지 항목이 많음
- 포트폴리오나 경력 설명을 붙여도 역할과 연결이 약함
- 회사/직무가 너무 추상적이라 맞춤 자기소개가 일반론으로 흐름
