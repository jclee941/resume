# 면접 답변 뱅크

## 1분 자기소개

```text
안녕하세요. 금융권 보안 인프라와 SIEM 운영을 실제 운영 절차로 연결해 온 이재철입니다.

KAI 폐쇄망 Linux/OA 운영에서 시작해, FSDC 감사 대응, 넥스트레이드 보안 인프라 구축과 운영까지 이어졌습니다. 최근에는 FortiGate HA 망분리, Splunk ES 탐지 룰, Slack/SMS 알림, FortiManager API 조회를 연결해 보안 이벤트를 인지하고 확인하는 흐름을 정리했습니다.

저는 보안 장비를 설정하는 데서 끝내지 않고, 반복 대응을 문서·스크립트·API 연동으로 남겨 감사나 장애 상황에서 설명 가능한 근거를 만드는 방식으로 일합니다. 지금은 보안 운영, 보안 인프라, Observability/SRE, DevSecOps 역할을 찾고 있습니다.
```

## 왜 우리 회사인가

```text
공고에서 본 핵심은 [공고 키워드]였습니다.

저는 이 부분을 단순 운영 업무가 아니라 반복 가능한 절차를 만드는 문제로 봅니다. 넥스트레이드 보안 운영에서 Splunk ES 탐지 룰, 알림 워크플로, FortiManager API 조회를 연결했던 경험이 있어, 귀사에서도 운영자가 매번 수동으로 확인하던 항목을 절차와 도구로 정리하는 데 기여할 수 있다고 판단했습니다.
```

## 가장 강한 프로젝트

```text
가장 강한 프로젝트는 넥스트레이드 보안 운영입니다.

문제는 보안 이벤트가 Splunk, 장비 콘솔, 알림 채널에 흩어져 있어 담당자가 어떤 이벤트를 먼저 보고 어떤 정책을 확인해야 하는지 흐름이 길어진다는 점이었습니다.

저는 Splunk ES Saved Search, Webhook, Slack/SMS 알림, FortiManager API 조회 절차를 연결해 이벤트 인지와 정책 확인 흐름을 정리했습니다. 이 경험은 단순 탐지 룰 작성이 아니라 운영자가 실제로 따라갈 수 있는 보안 이벤트 처리 절차를 만든 일입니다.
```

## 약점

```text
제 약점은 특정 퍼블릭 클라우드 운영 경험이 금융권 온프레미스·보안 인프라 경험보다 적다는 점입니다.

다만 Cloudflare Workers 기반 포트폴리오, Grafana/Prometheus/Loki, Terraform 기반 홈랩을 직접 운영하면서 edge와 관측성, IaC 경험을 넓히고 있습니다. 입사 후에는 회사의 클라우드 운영 표준을 먼저 따라가고, 제가 강한 보안 운영·증적화·자동화 관점으로 기여하겠습니다.
```

## 왜 이직/구직 중인가

```text
지금까지는 금융권 보안 인프라 구축과 운영을 현장에서 수행했습니다. 다음 단계에서는 그 경험을 보안 운영 자동화, 관측성, SRE/DevSecOps 쪽으로 확장하고 싶습니다.

장비를 운영하는 사람에서 끝나지 않고, 탐지·알림·정책 조회·운영 증적이 연결되는 구조를 만드는 역할을 찾고 있습니다.
```

## 포트폴리오 설명

```text
포트폴리오는 단순 이력서 페이지가 아니라 제 작업 방식을 보여주는 운영 표면입니다.

Cloudflare Workers로 운영하고 있고, resume data를 SSoT로 관리해 포트폴리오와 지원 플랫폼 문구가 어긋나지 않게 만들었습니다. Observability Platform에는 Grafana와 ELK 데모를 연결했고, Security Alert System과 Resume Portfolio는 제가 보안 운영·관측성·자동화를 어떻게 연결하는지 보여줍니다.
```
